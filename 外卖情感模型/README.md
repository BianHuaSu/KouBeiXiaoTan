# 外卖评价情感模型（端侧离线版）

一个专门判断外卖短评正 / 负 / 中性的小模型：只用 numpy 训练，导出 int8 权重，推理在手机浏览器里用原生 JavaScript 完成，不联网、不上传、不依赖云端大模型。

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `sentiment_model.json` | 模型本体：int8 权重（base64）、词典、温度 / 中性带、指标 |
| `外卖情感模型-手机版.html` | 手机端单文件推理页，模型已内联，双击/传到手机即可用 |
| `train_sentiment.py` | 训练脚本（读 `../_build/waimai_10k.csv`） |
| `predict.py` | Python 侧推理：单条 / 批量 / 评估 |
| `lexicon.json` | 情感词典（正 / 负，约 220 词），训练与推理共用 |
| `external_test.tsv` | 76 条自建外卖口语句（正负各半），用于回归检查 |
| `eval_cross.py` | 跨领域检查（酒店评论），只作参考，不参与调参 |
| `build_phone_page.py` | 把模型内联进单文件 HTML 的构建脚本 |

## 复现训练

```powershell
cd 外卖情感模型
python train_sentiment.py
```

依赖：Python 3.13 + numpy（无需 sklearn / torch）。数据来自公开语料 `waimai_10k.csv`（11,987 条，字段只有 `label,review`），随机种子固定为 20261124。

训练完会覆盖 `sentiment_model.json`，然后：

```powershell
python predict.py "这家麻辣烫太咸了，菜也少"
python predict.py --file external_test.tsv
python build_phone_page.py      # 重新生成手机页
```

## 方法

1. 文本归一化：只保留中文、字母、数字，转小写。
2. 特征：字符 1–4gram，FNV-1a 32 位哈希到 2^19 个桶，用哈希最高位定符号（signed hashing，减少碰撞偏置）。
3. 情感词典先验：统计正 / 负词命中数，前 4 字内出现「不 / 没 / 无 / 别 / 未」视为否定翻转（「不仅 / 不但」除外），生成 `LB / LP / LN` 三个桶特征。
4. 分类器：L2 正则逻辑回归，全批量 Adam；负类偏多，训练时做类别加权。
5. 数据增强：4,500 条模板合成句（菜品 × 方面 × 口语形容词、否定正向、反讽），权重 0.45，用来补语料里稀缺的「筋道 / 弹牙 / 炖得烂 / 不齁」等表达。
6. 导出：温度缩放标定（T=1.25），权重按 max|w| 线性量化到 int8，base64 存进 JSON；中性带 0.40–0.60。

## 指标（同一测试集，1,799 条）

| 版本 | Acc | F1 |
| --- | --- | --- |
| 旧版字符 bigram 朴素贝叶斯 | 84.99% | 71.64% |
| 本模型（int8） | **89.33%** | **83.73%** |

其他参考：

- 76 条自建外卖口语句：94.74%。**注意**：这批句子与增强模板风格同源，数字偏高，只能当回归检查，不能当独立泛化证明。
- 跨领域（酒店长评论 2,400 条）：69.67%。说明它是外卖域专用模型，不是通用情感模型。
- 手机页 JS 与 Python 推理逐条对比 76 条：最大概率差 5e-5，判定一致。

## 手机上怎么用

1. 把 `外卖情感模型-手机版.html` 传到手机（微信发给自己 / QQ / 数据线 / 网盘均可）。
2. 用手机浏览器打开（Android 用 Chrome / Edge / 夸克；iOS 用 Safari，或在「文件」App 里选择用浏览器打开）。
3. 页面打开后不再需要网络；模型 686 KB 已内联，输入框里的文字不会离开设备。

## 已知局限

- 反讽、双重否定、整段褒贬混写仍会错，例如「鸡肉嫩到咬不动，汤鲜到像白开水」需要靠 Agent 的反讽规则兜底。
- 长评论（酒店、数码）效果明显下降，建议先拆成单条观点。
- 公开语料没有店铺、菜品、星级字段，模型只学「这句话什么情绪」，不知道「哪家店、哪道菜」。
- 词表是人工整理的领域词典，遇到新梗（「yyds」「绝绝子」）需要补词后重训。
