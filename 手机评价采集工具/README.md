# 手机评价采集器

把**手机 App 里能看到、你有权访问的店铺评价**，转成 `CSV`，再接入口碑小探 Demo 做现场分析。

网页端通常只显示前几条评价，完整评价大多只在手机 App 里。这套工具不逆向 App 接口，也不破解验证码，只读取你手动打开页面上的可见内容。

## 四种采集方式

| 方式 | 适合场景 | 原理 | 需要什么 |
| --- | --- | --- | --- |
| **无障碍连续采集（推荐）** | 安卓手机连着电脑，评价页能连续上滑；要“滑的时候一直在读” | 手机端无障碍服务监听页面滚动/内容变化，持续把文字节点和坐标写进 `a11y_stream.jsonl`；PC 只读取新增快照并按版面切条 | 安卓手机、USB 数据线、USB 调试、安装一次 `a11y_helper.apk` |
| ADB + 界面树 | 不想装辅助 App，或只想逐屏抓 | `uiautomator dump` 读取当前屏节点和坐标，滑一屏读一屏 | 安卓手机、USB 数据线、USB 调试 |
| ADB + 截图 OCR / 截图 OCR 导入 | 页面是 WebView、自绘，界面树读不到 | 截图 → OCR → 版面解析 | 截图或录屏抽帧 |
| **淘宝语义树无障碍读取（推荐）** | 淘宝外卖评价页（Flutter 自绘） | 进淘宝时开一次 TalkBack 打开「触摸探索」，让 Flutter 语义树发布出来，逐屏 dump 读结构化标签；采完自动关掉 | 安卓手机、USB 数据线、USB 调试、系统里装有 TalkBack |
| ADB + 截图 OCR / 截图 OCR 导入 | 页面是 WebView、自绘，界面树读不到 | 截图 → OCR → 版面解析 | 截图或录屏抽帧 |
| 淘宝截图 OCR（兜底） | 淘宝语义树读不出来的异常情况 | 连续滑动 + 截图 + OCR，按「满意度」锚点切条 | 安卓手机、USB 数据线、USB 调试 |

**主链路现在是“无障碍连续采集”，不是 OCR，也不是逐屏 dump。** 手机端在页面滚动时自己读节点，PC 端只消费新增快照，所以不需要“滑一屏、停三秒、dump 一次”。

已列入监听白名单的 App：大众点评 `com.dianping.v1`、美团 `com.sankuai.meituan` / `com.sankuai.meituan.takeoutnew`、饿了么 `me.ele`、京东 `com.jingdong.app.mall`、淘宝 `com.taobao.taobao`。美团已在真机验证；饿了么本机未安装，代码已兼容但未现场验证；京东只验证到包名存在。

**淘宝现在也是无障碍读取，不再靠 OCR**：淘宝外卖评价页跑在 `io.unicorn`（阿里基于 Flutter 的自绘引擎），页面本身没有原生 View，所以平时 `uiautomator dump` 只有空容器。但 Flutter 引擎在系统「触摸探索（touch exploration）」打开时，会通过 AccessibilityNodeProvider 发布语义树。工具检测到前台是淘宝后会自动临时启用 TalkBack 打开触摸探索，再逐屏 dump 读语义节点，每张评价卡会得到一条结构化标签：

```
评价用户：e***7，满意度5，味道5星，包装5星，这家店的外卖包装干净卫生…，有商家回复
```

星级、用户名、正文一次拿全，`满意度` 就是整体星级，会出现 `2.5` 这种半星。

**TalkBack 只在采淘宝时用，进来开一次、采完关一次**：TalkBack 是开着时才有“开/关”提示音和朗读的来源，所以不做常驻——进淘宝时若触摸探索已经开着就直接读（完全不动设置），没开才开一次；采完把它摘掉，触摸探索随之关闭，单指单击恢复，其他 App 的无障碍读取不受影响。采集期间还会把媒体音量临时压到 0（原值记下、采完恢复），所以不会再一直响。想连续采多个淘宝页面、省这一次开关，可以加 `--tb-keep`。

**淘宝这条路的两个实测坑（已处理）**：① 大幅甩动后立刻 dump 会读到还没刷新的帧；现在淘宝用和美团同一套节奏「950px + 100ms 滑完立刻刹住」，但**滑完不再额外停 200ms**——dump 本身会等页面空闲，早一点发起就能把“等渲染”和“滑动”重叠掉，实测从 4.00s/屏降到 2.94s/屏，每屏照样稳定 1 条新卡；② 短信、通知浮窗会抢占最上层窗口，dump 会读到通知而不是淘宝，脚本会校验根节点包名，不对就等待重试。淘宝语义树不发布日期节点，所以淘宝的 `date` 列留空（不编造）。异常情况仍可用 `--ocr` 参数回退到截图 OCR。

**淘宝采集的两点噪音处理**：① 触摸探索开着时 TalkBack 会不停朗读界面元素、还播“开/关”提示音，采集期间工具会把媒体音量临时压到 0（原值记下来，采完恢复；想保留声音加 `--tb-sound`）；② 淘宝 `uiautomator dump` 一次要 3–5 秒，用「连续 N 秒没新增就停」会一屏 0 新增就误判到底，所以淘宝改成「连续 6 屏没有新卡才停」。

**淘宝采完切回美团读不到，怎么办（已自动处理）**：淘宝的 `dump` 会占掉无障碍事件的订阅，采完助手常处于“绑着但不写快照”的状态。关键点是**不能在淘宝前台重绑**——那时助手绑的是淘宝的 Flutter 窗口，重绑完切回美团照样读不到，还会被系统顺手摘出启用列表。所以改成：① 淘宝采完只关 TalkBack、补回被连带摘掉的服务，不做重绑；② 你回到美团/大众点评点“开始连续采集”时，工具先看最后一条快照是不是停在淘宝，是就先重启一次服务（此时前台才是对的 App，修得动），再开始滑；③ 助手若被系统摘出启用列表，启动时自动补回；④ 采集循环里连续 10 秒没有任何快照，再自动重启一次。实测「淘宝采完 → 切美团 → 直接采」10 屏拿到 12 条，中间无需任何手动操作。

淘宝命令行：`python a11y_collect.py --serial 设备号 --max-seconds 240`（淘宝会自动走语义树路径）；要回退 OCR 加 `--ocr`。GUI 里直接用「无障碍连续采集」即可，检测到淘宝会自动切换。实测节奏：每屏稳定新增 1 条，一屏约 2.9–3.4 秒（时间主要花在 `dump` 本身，不在滑动）。

**星级读取差异**：美团评价卡把评分写成文字节点（`商品5星`、`包装5星`），无障碍可以直接读真实星级；大众点评的星星是自绘的，界面树里没有星级节点，只能按“超预期/很棒/一般/很糟糕”近似，或用截图校准。不能把两者说成同一种能力。

三种方式最终都输出同一套 CSV；采集到 10 条以上会自动生成一个**预载分析页**，双击就能看结果。

## 快速开始

### 1. 安装依赖（只需一次）

双击 `安装依赖.bat`。它会在当前目录创建 `.venv`，安装：

- `rapidocr_onnxruntime`（OCR 引擎）
- `pillow`
- 以及 onnxruntime / opencv / numpy 等依赖

要求 Windows 10/11，已安装 Python 3.10–3.13（安装时勾选 Add Python to PATH）。

### 2. 启动界面

双击 `启动界面.bat`，打开“手机评价采集器”。

### 3. 手机无障碍连续采集（推荐）

#### 一次性准备

1. 手机打开“设置 → 关于手机 → 连续点版本号”开启开发者选项；
2. 开发者选项里打开 **USB 调试**；
3. 数据线连接电脑，手机弹窗点“允许 USB 调试”（勾选“始终允许”更省事）；
4. 打开工具，切到 **“无障碍连续采集”** 标签，点“检测设备”；
5. 点 **“安装/启用无障碍包”**。它会把 `a11y_helper.apk` 装到手机上，并把“口碑小探评价读取”追加到系统无障碍服务列表，不会覆盖小跳跳、小米钱包等其他服务；
6. 如果系统没有自动绑定，到手机 **设置 → 无障碍 → 已下载的服务**，手动打开“口碑小探评价读取”。

#### 每次采集

1. 手机上打开大众点评 / 美团 / 饿了么 / 京东 / 淘宝，**手动登录**，进入目标店铺的“评价”页；
2. 回到工具，确认设备已选中；
3. 设置“最多采集 / 最长秒数 / 开始倒计时 / 静默停止”；
4. 点 **“开始连续采集”**；倒计时内切回手机评价页，采集期间不要锁屏；
5. 工具会自动连续上滑；大众点评/美团/饿了么/京东走手机端无障碍服务持续读；如果前台是淘宝，会自动转成“Flutter 语义树”路径（进淘宝开一次 TalkBack，采完自动关掉，逐屏读语义节点，采集期间临时静音），不用你手动切；
6. 结束后点“打开输出目录”或“打开分析页”。

如果手机系统不允许 ADB 模拟滑动，点 **“手动滑动采集”**：你自己在手机上滑，手机端照样持续读取，不需要 `INJECT_EVENTS`。

建议第一次先设“最多采集 30、最长秒数 20”，跑通再放大。

#### 命令行方式

```bat
.venv\Scripts\python.exe a11y_setup.py --check
.venv\Scripts\python.exe a11y_setup.py
.venv\Scripts\python.exe a11y_collect.py --serial 你的设备序列号 --max-seconds 60
```

手动滑：

```bat
.venv\Scripts\python.exe a11y_collect.py --manual --max-seconds 60
```

只解析手机里已有的快照：

```bat
.venv\Scripts\python.exe a11y_collect.py --dump-only
```

### 4. 安卓 ADB 界面树采集（旧链路，保留）

1. 手机打开开发者选项和 **USB 调试**，数据线连接，手机点“允许”；
2. 在手机上打开外卖 App，**手动登录**，进入目标店铺的“评价”页；
3. 工具里点“检测设备”，下拉框出现设备序列号；
4. **解析方式选“界面树（推荐，准确切条）”**；
5. 设置“最多采集 / 最多滑动 / 开始倒计时”，点“开始采集”；
6. 倒计时内切回手机评价页，采集期间不要锁屏、不要手动乱滑；
7. 结束后点“打开输出目录”或“打开分析页”。

界面树模式会临时把系统动画缩放设为 0，避免 `uiautomator dump` 一直等页面 idle；采集结束会自动恢复原值。

**自动滑动被系统限制时**：直接点“抓当前屏（手动逐屏）”，你手动滑到下一屏，再点一次，结果会追加到同一批 `reviews_full.csv`。

### 5. 截图 OCR 导入

1. 手机截图，尽量只保留评价列表区域；
2. 把截图放进一个文件夹；
3. 工具里选“截图 OCR 导入”，选择文件夹；
4. “截图类型”：
   - **整屏多条评论**：一张截图里有多条评论，按日期和行间距切分；
   - **每张截图一条评论**：一屏就是一条，整段文字作为一条；
5. 点“开始 OCR”。

## 无障碍模式怎么工作

```
大众点评页面滚动 / 内容变化
        ↓
手机无障碍服务 onAccessibilityEvent
        ↓ 约 120ms 防抖
读取当前窗口的文字节点（text / 坐标 / 是否可滚动）
        ↓
追加一行 JSON 到 App 内部 files/a11y_stream.jsonl
        ↓
PC 端 run-as 读取文件，按 seq 取新增快照
        ↓
uiauto_core.parse_ui_nodes 按日期锚点切卡片
        ↓
merge_ui_rows 去重、拼接半屏截断
        ↓
reviews_full.csv / reviews_demo.csv / 预载分析页
```

关键点：

- 手机端**不截图、不调用 `uiautomator dump`**；
- PC 端读取的是服务写出的快照，不是等界面静止后 dump；
- 服务只把真正的 `text` 节点发出来，`content-desc` 里的“图片11/正文3/评论按钮”不会带进正文；
- 一次滑动过程中通常能拿到 2–6 个快照，PC 按 `seq` 取新增，所以能读到滚动中间态；
- 页面底部半条评价会先被截断，滚上来后由 `merge_ui_rows` 用包含关系补全。

## 速度与星级

- **无障碍模式**：默认「100ms 快滑 + 滑完立刻刹住 + 停 200ms 读快照」，每次约 950px（0.86→0.51 屏高），PC 每 0.30s 读一次流；不等待 `uiautomator dump`。真机实测（同一店铺、真实页面、Redmi 2407FRK8EC）：一次滑走 2–3 张评价卡，55 条约 60 秒出数；
- **「刹住」是怎么回事**：`adb input swipe` 在手指抬起后界面还会惯性再滑一段，快滑时这段惯性经常把两条评价带过去（实测 250px 滑程平均 2.2 条/次、950px 仍有跳条）。所以滑完立刻补一发 `input motionevent DOWN` + `CANCEL`，把惯性吃掉——CANCEL 不触发点击，实测滑完前台仍是评价列表。加了刹住后 950px 滑程每次稳定滑走 2–3 条且整屏不跳。不想要这层保险可以加 `--no-brake`；
- **淘宝也是这套节奏**：滑动参数完全共用（950px / 100ms / 刹住），差别只在“读”——淘宝必须等 `uiautomator dump` 拿语义树，所以滑完不等停、直接 dump（`--tb-settle` 默认 0）。真机实测每屏约 2.9–3.4 秒、稳定 1 条新卡：30 屏 25 条 102 秒；
- **淘宝为什么快不起来**：dump 一次 2.5–3.3 秒是 Flutter 页面等空闲的固定开销，换 compressed dump、dump 到 stdout、把滑程拉到 1900/2400px 实测都更差（后者只有 0.3 条/屏）；截图 OCR 约 2.4 秒/条且正文有断行错字。所以淘宝的现实上限就是 3 秒左右一条，不是参数没调好；
- **服务轮询**：除了 `TYPE_VIEW_SCROLLED`，服务每 600ms 轮询一次当前窗口；美团的自绘评价列表不发滚动事件，靠轮询才能在滑动中持续读到新卡片；
- **界面树模式**：仍是逐屏快照，默认 `--interval=0.35`、`--swipe-duration=320`，每屏约 3 秒；
- **星级**：美团的 `商品5星` / `包装5星` 是文字节点，无障碍可直接转成 5.0；Android `RatingBar` 的 `RangeInfo` 也能直接读；
- **星级只认卡内节点**：页面顶部固定栏的“评分 4.4”和正文里的“★★★麻辣拌★★”都曾被误算成星级（前者让整卡变 4.3，后者把 5/5/3 平均成 4.3）。现在顶部 12% 固定栏不参与、只有整段都是星号才算星级，实测 55 条星级全为整/半星；
- **商家回复不算评价**：店铺公告/置顶回复（“感谢您对本店的支持和信任……”）会以“首条评价卡上方的孤立正文”出现，星级为空。现在按模板句剔除，实测 12 条复查 0 条空星级；
- 大众点评的星星是自绘的，无障碍/界面树里没有星级节点；不截图时只能按“超预期/很棒/一般/很糟糕”标签校准（`5 / 4.5 / 2.5 / 1`），是近似值；
- 需要逐条真实半星，用旧界面树链路勾“截图校准星级”（或 CLI 加 `--with-shots`），每屏多花约 0.6 秒截图，按橙色星星逐颗数；
- 无障碍模式为了连续读，不截图；所以大众点评仍是标签近似，美团/有 `RatingBar` 的 App 是真实星级。不能用同一句话把两者混为一谈。

## 输出文件

每个采集任务生成 `output/时间_任务名/`：

| 文件 | 用途 |
| --- | --- |
| `reviews_full.csv` | 完整字段：`rating,review,user,date,source,page` |
| `reviews_demo.csv` | Demo 上传专用：`rating,review` |
| `reviews_dropped.csv` | 采集时读到、但被判为无效（正文为空 / 商家回复 / 太短）的样本，逐条列出原因，方便复核 |
| `collect_stats.json` | 统计口径：`raw = kept + dropped`，含各原因的条数；预载页据此算“原始 / 清洗” |
| `口碑小探-手机采集.html` | 采集 ≥10 条时生成，双击直接看分析 |
| `ui/page_001.xml` | 界面树模式下每屏原始 XML，排查字段用 |
| `ui_raw.txt` | 界面树/OCR 的原始文本，排查切条用 |
| `ocr_raw.txt` | OCR 模式专有：识别出的文字行 |
| `screens/001.png` | 勾选“截图校准星级”时才生成，用于数半星 |

无障碍模式的 `source` 字段按来源 App 区分：`a11y_dianping`、`a11y_meituan`、`a11y_eleme`、`a11y_jd`；旧数据可能仍是 `a11y`。页面来源写“大众点评/美团/饿了么/京东 · 手机无障碍服务（边滑边读）”。

### “原始 / 清洗”怎么算

采集阶段会把读到的每一条候选卡片都记一笔：进了 CSV 的叫有效，被判为“正文为空 / 商家回复 / 太短”的叫被过滤，所以

```
原始 = 有效 + 采集端过滤       清洗率 = (原始 - 分析端有效) / 原始
```

以前只统计有效样本，预载页拿到的 `raw` 就等于有效条数，才会出现“原始 66 条 · 清洗 0 条（0%）”。现在 `collect_stats.json` 会跟着预载页一起进去，报表显示的是全流程剔除（采集端 + 分析端）的条数和占比；`reviews_dropped.csv` 可以逐条看为什么被丢。

## 常见问题

**`adb devices` 为空 / 提示 unauthorized**

- 换一根能传数据的 USB 线，别用只能充电的线；
- 手机通知栏把 USB 模式改成“传输文件 / MTP”；
- 开发者选项里关闭再打开 USB 调试，重新插拔；
- 手机上点“允许 USB 调试”；
- Windows 可能需要装手机厂商的 USB 驱动；
- 仍不行时，用“截图 OCR 导入”绕过 ADB。

**提示没有检测到已授权设备**

先解锁手机，再重新插拔线；在手机上点“允许 USB 调试”。如果之前点过“拒绝”，到开发者选项里点“撤销 USB 调试授权”再重连。

**安装辅助 App 被拦截**

小米/Redmi 常见 `INSTALL_FAILED_USER_RESTRICTED`。到手机设置里允许本次安装，或关闭“监控安装应用/安装验证”；也可以用 `adb install --no-streaming -r a11y_helper.apk` 手动装。

**服务已启用，但 PC 读不到快照**

1. 打开辅助 App “口碑小探评价读取”，点“刷新服务状态”；
2. 到系统无障碍设置里把服务关一次再开；
3. 手机上在目标 App 评价页上下滑一下，让服务产生快照；
4. `python a11y_setup.py --check` 看服务是否在 `Bound services`；
5. 仍不行时重新安装 `a11y_helper.apk`（debug 版），PC 才能用 `run-as` 读内部文件。

**装了旧版 APK 时只监听大众点评**

旧版 APK 才是这样。现在 `a11y_config.xml` 的 `packageNames` 是：

`com.dianping.v1,com.sankuai.meituan,com.sankuai.meituan.takeoutnew,me.ele,com.jingdong.app.mall`

如果手机里装的还是旧版，重新执行“安装/启用无障碍包”覆盖安装即可。新增 App 时，同时改这个配置和 `ReviewAccessibilityService.java` 里的 `TARGET_PKGS`。

**美团页面滑动了，但快照不增加**

美团评价列表是自绘控件，不一定发 `TYPE_VIEW_SCROLLED`。当前 APK 已每 600ms 轮询一次当前窗口；如果仍不增加，确认装的是最新 `a11y_helper.apk`（2026-11-25 之后的版本），而不是旧版。

**采集时手机页面不滑动 / 提示 INJECT_EVENTS**

这是手机系统拒绝了 ADB 注入触摸，不是采集器没发滑动命令。

小米 / Redmi / HyperOS：

1. 设置 → 更多设置 → 开发者选项；
2. 找到 **「USB调试（安全设置）」**，打开；
3. 有的机型需要登录小米账号、插入 SIM 卡后这个开关才出现；
4. 开启后关闭再打开一次「USB 调试」，或重新插拔数据线；
5. 回到工具重新采集；也可以直接用“手动滑动采集”绕过。

**采集到一半停了**

- 页面滑到底了；
- 连续 `--idle-stop` 秒没有新增；
- 达到 `--max-reviews` 或 `--max-seconds`；
- 手机锁屏 / App 被切走；
- 评价页出现登录或验证，需要先在手机上手动完成。

**评论重复 / 半截**

工具按正文做包含关系去重：半屏截断的短文本会被更完整的正文吸收；完全相同的正文只保留一条。无障碍模式会在滚动中间态多次看到同一条，最终合并成一条。

**星级不准**

分情况：

- 美团评价卡有 `商品5星` / `包装5星` 文本，无障碍能读真实星级；
- Android `RatingBar` 有 `RangeInfo`，能读真实值；
- 大众点评自绘星星没有节点，无障碍只能按心情标签近似；要真实半星请用“安卓 ADB 采集 → 界面树 + 截图校准星级”。

**为什么不做 App 接口逆向 / 验证码识别 / 代理池**

那会绕过平台安全机制，也有账号和合规风险。本工具只读取你手动打开、且有权访问的页面，属于人工采集的自动化辅助。

## 已验证与未验证

已验证（2026-11-25，Redmi 2407FRK8EC，1220×2712）：

- 无障碍服务能安装、启用并进入系统 `Bound services`；
- 服务写出的 `a11y_stream.jsonl` 能被 PC 用 `run-as` 读取；
- 大众点评自动连续滑动 15 秒读到 27 条、20 秒读到 37 条真实评价；
- 美团真机自动连续滑动 20 秒读到 34 条真实评价，`pkg` 字段为 `com.sankuai.meituan`；
- 美团 `商品5星` / `包装5星` 能解析成 `5.0`；带 `3.0` 的差评也能读出来；
- 半屏截断会由 `merge_ui_rows` 补全；平台提示、加盟广告、推荐菜列表、评论按钮等脏行已过滤；
- 采集 ≥10 条自动生成预载分析页；
- GUI 三标签能创建，新增代码 `py_compile` 通过。

未验证 / 已知限制：

- 饿了么本机未安装，代码已列入白名单但未现场验证；京东只验证到包名存在，评价页布局未验证；
- 大众点评星级仍是标签近似，不是逐颗星星；美团/`RatingBar` 是真实值；
- 不同手机分辨率、字体大小、深色模式会影响坐标切条，首次使用建议先小批量试跑；
- 部分系统会限制 `input swipe`，此时用手动滑动模式；
- 服务内部文件会随采集增长；单次几十秒没问题，长时间采集建议重启一次服务，让文件重新开始。

## 打包

不要把以下内容打进对外压缩包：

- `.venv/`（依赖，体积大，接收方自己装）
- `output/`（含你的采集结果）
- `_build/`（本机编译工具链和中间产物）
- 任何含账号信息的截图

应打包：源码、`requirements.txt`、两个 `.bat`、`README.md`、`adb/platform-tools/`、`a11y_helper.apk`、`a11y_app/`、`口碑小探-demo.html`。
